## Architecture

Next.js 15 App Router, React 19, TypeScript, Tailwind v4, Firebase (Auth + Firestore). Path alias `@/*` maps to the repo root. There is no `src/` directory.

### Route groups don't appear in URLs

`app/(admin)`, `(auth)`, `(quiz)`, `(user)`, `(dev)` are route groups, so admin pages are served at `/dashboard`, `/quizzes`, `/users`, `/quiz-reports` (not `/admin/...`; `/settings` is still gated in the middleware but the page was removed in P7.3). The quiz lobby and exam are `app/(quiz)/q/[id]` at `/q/<quizId>` (the address never contains the access code); `app/(quiz)/[code]` only resolves older `/<ACCESSCODE>` links to `/q/<id>`; `/join` is the quiz list and code-entry page.

### Auth and session flow (spans several files)

1. Client signs in via Firebase Auth (`lib/actions/auth-core.ts`, wrapped by `contexts/auth-context.tsx`, which the root layout loads on every page, so keep `auth-core` small). Profile changes are in `auth-account.ts` and second-factor enrolment in `auth-mfa.ts`; only the profile page imports them (the MFA setup dialogs through `React.lazy`).
2. `lib/actions/session.actions.ts` posts the ID token to `app/api/auth/session/route.ts`, which verifies it once, reads the role from `users/{uid}` while it makes the session cookie, and sets `session` (Firebase session cookie, 14 days, httpOnly), `user_role` (httpOnly hint) and `signed_in=1` (readable hint, proves nothing; without it the client skips `/api/auth/session/check`). Everything else (`lastLoginAt`, a new person's profile, the `role` claim, the activity log) runs in `after()`, never as an un-awaited promise. Sign-in, sign-up and sign-out are logged on the server (`lib/server/activity.ts`), not from the browser. `DELETE` signs out this browser only; `?scope=all` with a Bearer ID token revokes refresh tokens (Profile → Security → Sign out of all devices).
3. `middleware.ts` runs on the edge, so it can only check that the `session` cookie *exists* and read the `user_role` cookie as a hint; it never proves anything. It checks the real admin paths (`/dashboard`, `/quizzes`, `/users`, `/quiz-reports`, `/settings`) first, then an allowlist of public paths (anything under `/q/`, the quiz/attempt/leaderboard API routes, which verify tokens themselves, and old `/<CAPITALS5to10>` quiz links). It also 404s the dev-only pages in production (`lib/dev-routes.ts`) and passes the URL on in an `x-pathname` header.
4. `app/(admin)/layout.tsx` is a **server component** and is the real admin gate: `lib/server/admin-access.ts` verifies the session cookie with Firebase (revocation included) and reads the role the way the Firestore rules do (claim, or `users/{uid}.role`), and redirects anyone else before anything renders. `AdminShell` (client) is only the admin chrome. Roles are in `constants/role.ts`.
5. `app/(user)/layout.tsx` (My quizzes, leaderboard, profile) is a server layout; its client `UserGate` shows the page at once when the session cookie is valid, otherwise a placeholder while auth resolves, and redirects to `/sign-in?redirectTo=<path>` once the browser knows no one is signed in. `lib/navigation.ts` `safeRedirectPath` keeps `?redirectTo=` on this site. Starting a quiz attempt needs sign-in (the lobby is open to everyone).
6. `firebase/client.ts` starts Auth with `initializeAuth` and **no popup resolver** (so Google's `gapi` script and iframe don't load on every page); `signInWithPopup` must be given `browserPopupRedirectResolver` (done in `lib/actions/auth-core.ts`). `auth-context` caches user data in localStorage (`lib/services/session.service.ts`) and refreshes the session every 30 minutes.

### Data layer

**The browser never uses Firestore** (`firebase/client.ts` has no `db`, and the client bundle has no Firestore SDK). A person's own profile changes and activity log entries go through `PATCH /api/account/profile` and `POST /api/account/activity` (`lib/server/account.ts`; `recordActivity` in `lib/actions/activity.ts`). Everything a player reads or writes, and every quiz an admin creates, edits or deletes, goes through server routes (Admin SDK, `lib/server/*`), and the browser calls them with `lib/api-client.ts` (`apiRequest`, Bearer ID token) through `lib/quizzes-api.ts` and `lib/exam/api.ts`:
- `GET /api/quizzes` and `GET /api/quizzes/[quizId]`: the public quiz shape (`PublicQuiz` in `lib/quiz-data.ts`: **never the access code**, owner or answer settings) plus question counts (from the quiz's stored `questionCountByDifficulty`). Both, and each level's question set used by `startAttempt`, go through Next's data cache (`lib/server/cache.ts`, tags `quizzes` and `quiz:<id>`); the admin quiz routes call `invalidateQuiz(id)` after every create/save/delete, so **any new code path that writes a quiz or its questions must call it too**. Not CDN-cached (`no-store`). `POST /api/quizzes/resolve`: access code → quiz id (the only place a code becomes a quiz).
- `POST /api/attempts/start` (checks the access code on the server and needs sign-in), `GET`/`PATCH /api/attempts/[id]` (resume, autosave), `POST /api/attempts/[id]/submit`, `GET /api/attempts/[id]/result` (a finished attempt's stored result and review, owner only; shown at `/my-quizzes/<attemptId>` with `ResultsScreen`, the same display as right after a quiz).
- `GET /api/leaderboard` (ranked on the server: the first 50 rows, `total`, and the caller's own row as `me`) and `GET /api/my-attempts`: display names only, never emails. All-time boards read precomputed docs: `leaderboard/{quizId}_{uid}` (a person's best on a quiz, overall and per level) and `userTotals/{uid}` (sum of bests), which the **submit transaction** updates (`lib/server/leaderboard-store.ts`; the arithmetic is pure, in `lib/leaderboard-stats.ts`, with a sortable `rankKey`). Week/month boards are built from that period's `responses` and cached 30 s. Quiz delete and user delete keep them in step; a name change copies the new name over in `after()`. **Any new code that writes or deletes `responses` must update them too**, or rerun `npm run backfill:leaderboard` (dry run unless `-- --apply`; rebuilds both from `responses` and sets each quiz's `responseCount`).
The browser never sees which option is right until a submit returns the review; see "The quiz-taking flow" below. `firebase/firestore.ts` is now **types only** (`Quiz`, `QuizQuestion`, ...): no runtime code, so the server can import it. `lib/quiz-data.ts` (`quizFromData`) holds the field defaults.
- **Admin routes** (`app/api/admin/*`, guarded by `requireAdmin` in `lib/server/admin-access.ts`; browser calls in `lib/admin-api.ts`): quizzes (list, with the stored `responseCount` once `responseCountTracked` is set, otherwise a `count()`; open with the answer key, create, save in one transaction with a `version` check; **delete = move to the trash**: `deletedAt` on the quiz, hidden from players, its leaderboard rows removed and rebuilt on `restore`, results kept; `delete-forever` needs the quiz already in the trash and its exact title; any new player-facing read of `quizzes` must treat a quiz with `deletedAt` as missing), users (list, change role = `role` claim + profile + sessions revoked on demotion, delete = Auth account + profile), `reports` (paged) and `stats` (aggregations). Logic in `lib/server/admin-quizzes.ts`, `admin-users.ts`, `admin-reports.ts`. **`lib/quiz-schema.ts` is the one description of a quiz** (types, `validateQuizInput` used by editor and server, stored shape, legacy handling); `lib/quiz-writes.ts` plans question writes. `npm run migrate:questions` moves old shared `questions` collections into the per-level ones (dry run unless `-- --apply`).

Questions are stored per difficulty in subcollections `quizzes/{id}/questions_{easy|medium|hard}` (see `firebase/quizDifficulty.ts`), with a fallback to the legacy `quizzes/{id}/questions`. **Question model v2** (`docs/ADMIN_PLAN.md`, A1): a question has `type` (`single`: one correct option; `multiple`: at least one, scored all or nothing: the picked set must equal the correct set), options `{ text, isCorrect, rationale? }` (a reason per option, besides the overall `explanation`) and `schemaVersion: 2`. Answers are **lists** of option positions everywhere (`AnswerMap = Record<questionId, number[]>`, `[]` = unanswered); the server's key is `correct: number[]`. `normalizeQuestion` (stored docs, any older shape) and `upgradeStoredQuestion` (the snapshot inside an attempt that began before v2) are the only places that read old shapes; `toPicks` (`lib/exam/answers.ts`) reads old single-number answers. A level's text is capped by `LIMITS.maxLevelBytes` (an attempt copies it into one document). Per-difficulty `difficultySettings` (duration, `pointsMultiplier`) live on the quiz doc; see `docs/DifficultySettings.md` and `utils/difficulty-helpers.ts`. Final score is raw % (of every question in the attempt) times the multiplier (1 when a level sets none), rounded and capped at 100, computed only by `lib/exam/scoring.ts` on the server; the response also stores `rawPercent`, `correctCount` and `pointsMultiplier`. `firestore.rules` in the repo is the **final** ruleset (S4.3 of the performance plan): it denies every browser read and write, admins included; only the Admin SDK on the server touches the database. Any change to it must be deployed with `firebase deploy --only firestore:rules --project ageno-quiz-af3ff` (test it first: `__tests__/firestore-rules.test.ts`). So a new screen, player or admin, must get its data from a server route.

### Quiz format, import and export

"Ageno Quiz Format" v1 is JSON (envelope `{ format: "ageno-quiz", version: 1, quiz?, levels }`; `docs/ADMIN_PLAN.md` 3.3). The code is pure (no Firebase, runs in the browser):
- `lib/quiz-format/`: `read.ts` (JSON → `ParsedImport`: rows, level settings, file-level issues; forgiving, never throws), `checks.ts` (`checkRows`: the schema's rules through `checkQuestion` in `quiz-schema.ts`, plus warnings; `summarize`), `validate.ts` (`validateQuizFile`, the whole-file report), `json-schema.ts`, `write.ts` (export JSON/CSV/text with ids), `instructions.ts` (the AI rules, one source for `SKILL.md` and the "Copy AI instructions" text), `zip.ts`. `lib/quiz-import/`: `table.ts` (tab/comma/semicolon, quotes), `spreadsheet.ts` (columns by header), `text.ts` (the plain-text format), `apply.ts` (`applyImport` add/replace/update, `diffQuestions`: counts like `planQuestionWrites`), `templates.ts`. A reader returns rows with errors instead of refusing a file; every route ends in the same `ParsedImport`. `lib/quiz-schema.ts` stays the one place that says what a valid question is.
- **Generated files, never edit by hand:** `npm run build:format` writes `public/ageno-quiz/*` (schema, templates, example, the skill as a zip) and `skills/ageno-quiz-format/*` (`SKILL.md`, `schema.json`, `validate.mjs`, examples) from that code; `npm run build:format -- --check` fails when they are stale (`format-artifacts.test.ts` runs it). Change `LIMITS`, the examples or the instructions, then run the script and commit the output. `middleware.ts` serves `/ageno-quiz/*` without sign-in.
- UI: `components/admin/quiz-import/` (`ImportWizard` at `/quizzes/import`, `SourceStep`, `CheckStep` which edits a row with the editor's `QuestionCard` over `editorReducer`, `TargetStep`, `plan.ts`); the editor's Import button opens the same steps in a dialog (`quiz-editor/ImportDialog.tsx`) and only changes the draft. A new quiz from an import is created **closed** unless the admin opts in. `/quizzes/ai` is the "AI & formats" page.
- A save with more than 500 writes (`updateQuiz` → `updateQuizInChunks` in `lib/server/admin-quizzes.ts`) is not atomic: it sets `importing: { state, at }` on the quiz, writes in chunks of 450, writes the quiz fields last and clears the flag. While the flag is set `startAttempt` answers `quiz_updating` and other saves are refused (a `running` mark older than 3 minutes, or `interrupted`, can be taken over). A failure answers `update_interrupted`; sending the same request again finishes it, sending the previous contents puts the quiz back, and the admin detail carries `updateUnfinished` so the editor can say so. Any new code that reads a quiz's questions for players must keep refusing a quiz with `importing`.

### Server-rendered data pages

Data pages are server `page.tsx` files that read through `lib/server/*` and pass plain-JSON DTOs to a `*Client.tsx` component (`JoinClient`, `MyQuizzesClient`, `LeaderboardClient`, `AttemptReview`, `DashboardClient`, `QuizzesClient`, `UsersClient`, `ReportsClient`; the lobby's `QuizClient` takes `initial`). The client shows that data at once and fetches through the API only when it got `null`, or for Retry, filters and paging. DTO types and converters are in `lib/player-data.ts`. `/join` is static and `/q/[id]` on-demand ISR, both rebuilt by the cache tags in `lib/server/cache.ts`. `(user)` pages use `getSessionUser()` (`lib/server/session.ts`) and the `UserGate` client component; there is deliberately **no server-side redirect** there (a browser signed in to Firebase without a session cookie would loop with the sign-in page). Admin pages load with `loadForAdmin()` (`lib/server/admin-access.ts`), which checks the admin itself: a page must not rely on its layout's check. Page tests import the `*Client` components.

### Site shell and design system

- Pages never render a header or footer. `components/layout/SiteFrame.tsx` (header, the single `<main id="main-content">`, optional footer) is used by the `(auth)`, `(quiz)`, `(user)` and `(public)` layouts. `(admin)` has its own layout. Don't put `<main>` in a page.
- Tokens live in `app/theme.css` (Agenoverse port) and brand utilities in `app/globals.css`. The default Tailwind palette still exists until P7.6, and `<body>` is still light. New or redesigned screens sit on a dark surface (`data-theme="dark"` + `bg-bg text-text`) and use token classes (`bg-surface`, `text-text-muted`, `border-border`, `text-accent`), not `gray-*`/`indigo-*`.
- Primitives are in `components/ui/` (import from `@/components/ui`); use `cn()` from `lib/utils.ts`. Don't add a component library.

### Large files to know about

- **The quiz-taking flow.** `app/(quiz)/q/[id]/client.tsx` (~270 lines) only wires things together: `hooks/useQuizLoader.ts` (one request: the public quiz plus question *counts* per level) → lobby (`components/quiz/lobby/`) or `ResumeAttempt` → `components/quiz/exam/QuizAttempt` (those two load with `React.lazy`, prefetched once the lobby is on screen, to keep the lobby's first load small) (one attempt: `ExamShell`, `QuestionView`, `QuestionNavigator`, `SubmitDialog`, then `ResultsView`). Start/Resume/Retry call the attempt routes through `lib/exam/api.ts` (Bearer ID token; **no guests**: every attempt route needs sign-in, and the lobby's access-code field is just forwarded to the server, which checks it on start) and turn the answer into a seed with `lib/exam/seed.ts` (corrects the server clock against the device clock). Server side: `lib/server/attempts.ts` (`startAttempt`, `getAttempt`, `saveProgress`, `submitAttempt`; Firestore `attempts/{id}` holds a snapshot of the questions with their key, the deadline, answers, flags and counters, readable only through the Admin SDK) and `lib/server/request.ts`. A submit runs in one transaction (exactly once; a repeat returns the stored result), writes `responses/{attemptId}` with a compact answer **`sheet`** (`{ [questionId]: { p: picks, ok? } }`, `schemaVersion: 2`; there is no per-answer document any more, so a submit writes a handful of documents; `lib/response-sheet.ts`; older results keep `responses/{id}/answers/*` until `npm run backfill:sheets` (dry run unless `-- --apply`) builds their sheet), and a submit later than deadline + 30s is not read: the last autosave counts and the result says `late`. Integrity signals (tab hidden, window blur, left fullscreen) are numbered **events** the browser reports with the autosave and the submit; `lib/exam/integrity.ts` `applyEvents` stamps them with the server's time, ignores repeats by `seq`, and derives the counts from them (a count sent by the browser is ignored). They end up on the response (`tabSwitchCount`, `blurCount`, `fullscreenExits`, `integrityEvents`). State for an attempt (answers, flags, submit guard, autosave to the device under `ageno:quiz:attempt:<quizId>:<uid>` and, debounced, to the server) is in `hooks/useQuizAttempt.ts`; pure helpers are in `lib/exam/` (`normalize.ts`, `scoring.ts`, `integrity.ts`, `answers.ts`, `review.ts`, `storage.ts`). Before a submit the browser learns only each question's `type` and, for `multiple`, `pickCount` ("Choose 2"): never the key, a reason or an explanation. The result's **review is not stored**: `attempts/{id}.result.review` is `null` and `buildReview` rebuilds it from the attempt's own question snapshot when a result is returned (submit and `GET /api/attempts/[id]/result`), so reasons live once; results stored before that keep their review, and `upgradeResult` reads them into the current shape (`ReviewItem = { correct: number[], explanation?, optionRationales? }`). Mount `QuizAttempt` with `key={attemptId}`: a retry is a new attempt. `Quiz.examMode` (`practice` default, `strict`) decides what leaving fullscreen does (`FullscreenNotice` vs `FullscreenGate`, exits counted in `fullscreenExits`); Start/Resume/Retry request fullscreen from the click (`lib/exam/fullscreen.ts`). While an attempt runs, `useExamMode` (`components/layout/QuizFrame.tsx`) removes the site header.
- `components/admin/quiz-editor/`: the one admin quiz editor (create and edit), on `editor-state.ts` (reducer) and the shared schema; `components/admin/AdminPage.tsx` frames the admin pages. Speed tools (A3): questions show as **Cards** (`QuestionCard`) or a **Grid** (`QuestionGrid` over the pure `grid.ts`: cell edits, the Correct column, pasting spreadsheet rows); `LevelsSection` holds the selection (copy / move / delete across levels, all through the reducer's `setQuestions` with one-step Undo; a moved or copied question is new, with no id); `PlayerPreview` draws the real `QuestionView` / `QuestionReview`; `ChecksPanel` shows `lib/quiz-checks.ts` (advice only); `useDraft` + `draft-storage.ts` keep unsaved edits in localStorage (`ageno:admin:draft:<quizId|new>`, device only, every access allowed to fail). `hooks/useDuplicateQuiz.ts` + `lib/quiz-duplicate.ts` make a closed copy of a quiz through the normal create route. Question pictures: `ImageField` posts the file to `POST /api/admin/images` (`lib/server/image-upload.ts`, rules in `lib/quiz-images.ts`: 2 MB, PNG/JPEG/WebP/GIF by their bytes), which stores it with the Admin SDK in the bucket (`FIREBASE_STORAGE_BUCKET`, default `<project>.appspot.com`) and returns a download-token address for `imageUrl`; the browser never uses Storage and `storage.rules` is deny-all. The editor form swallows Enter in text boxes; only the Save button submits.
- `lib/admin-analytics.ts` (score and time bands, report summary, CSV with formula-safe cells) feeds the admin dashboard and reports; charts are `components/admin/DistributionChart.tsx` (plain bars, no chart library). `lib/leaderboard.ts` (the board DTO and the builders) ranks by the stored (already weighted) score: one quiz = each person's best attempt; overall points = sum of each person's best score per quiz.

### Build config

`vercel.json` pins functions to `fra1`, next to Firestore (`eur3`); change both together. API routes add a `Server-Timing` header (`lib/server/timing.ts`) for finding slow steps in the Network tab. `<SpeedInsights />` is in the root layout.


`next.config.mjs` has no webpack overrides (the Node polyfills were removed in S4.4; the browser code needs none, so don't import Node modules in client code). `ANALYZE=true npm run build` writes bundle reports to `.next/analyze/`. Budget: public pages under 170 kB First Load JS (sizes in `docs/PERFORMANCE_PLAN.md`, S4). `package.json` declares `"sideEffects": ["*.css"]` so webpack can drop unused re-exports of barrels like `components/ui`: a module that must run for its side effects alone (a bare `import "./x"`) has to be added to that list. Remote images are allowed only from `firebasestorage.googleapis.com` (`images.remotePatterns`).
